# ГигаДок · демонстрация проверки зрения

Веб-приложение для iPad на подставке, расстояние 40–70 см. Контролирует приблизительный взгляд на экран и прикрытие каждого глаза ладонью. После калибровки: тренировка свайпа, по 5 символов E для правого и левого глаза, результаты без медицинской оценки.

Главная страница предлагает два режима:
- **Проверка зрения** — существующий сценарий с символом E, свайпами и итогами.
- **Проверка API** — камера, калибровка и живой ответ общего VideoAnalyzer (`valid`, `gaze`, `covered`, `reason`), с возможностью раскрыть полный ответ и параметры калибровки. Это локальный API библиотеки, а не запрос к серверу.

Оба режима доступны по одному адресу и входят в `dist`. Камера запускается только кнопкой «Включить камеру». Кнопка «Выбрать режим» возвращает на главную, останавливает камеру, отменяет незавершённый запуск и очищает текущую проверку. Отдельный пример на порту 5174 остаётся примером установки пакета, для обычного выбора режимов он не нужен.

## Запуск

Нужен Node.js 22.18+ (рекомендуется 24) и pnpm. Версии зависимостей закреплены в `pnpm-lock.yaml`.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Откройте `http://localhost:5173` на том же компьютере. Для камеры разрешите доступ в браузере. `pnpm build` создаёт папку `dist`; `pnpm preview` показывает собранную версию локально.

## iPad и HTTPS

На iPad адрес `http://192.168.…` не разрешает доступ к камере. Разместите **содержимое `dist`** на статическом HTTPS-хостинге с доверенным сертификатом и откройте адрес в Safari. Также подходит локальный HTTPS-сервер с сертификатом, которому доверяет iPad. В этой версии публикация не выполнялась. Обычный HTTP по локальной сети пригоден лишь для просмотра интерфейса.

Не встраивайте приложение в чужой iframe без разрешения камеры. Рекомендуется открывать напрямую в Safari. Точную минимальную версию iPadOS и список поддержанных моделей нужно определить по приёмке на устройствах; проверки на настольном браузере их не заменяют.

## Подключение анализа видео в другой проект

Анализ выделен в независимый пакет **`@gigadoc/video-analysis`**: `VideoAnalyzer`, `Calibration`, чистые функции и TypeScript-типы. Он принимает видео из вашего проекта, не запрашивает камеру и не содержит интерфейса демо.

```sh
pnpm package:library
```

Готовый архив: `artifacts/gigadoc-video-analysis-0.2.0.tgz`. Его можно установить в другом проекте через `npm install ./gigadoc-video-analysis-0.2.0.tgz` или `pnpm add`. В архив включены модели и WASM.

Полная инструкция и API: [docs/video-analysis.md](docs/video-analysis.md). Самостоятельный пример-потребитель: [examples/integration](examples/integration), использует пакет из архива, а не исходники демо. После сборки архива выполните `pnpm --dir examples/integration install`, затем `pnpm --dir examples/integration dev`.

`pnpm test` использует встроенный тестовый модуль Node и проверяет геометрию, калибровку, стороны, свайпы, паузы, свежесть данных и подсчёт.

Локальный браузерный стенд: `http://localhost:5173/tests/browser.html`. Он явно помечен как тестовый, подменяет ориентиры и использует canvas-поток вместо камеры. Через список «Кадр» можно пройти сценарий, вызвать паузу, отказ доступа, замерший поток и отключение камеры. Счётчики показывают остановку дорожек и закрытие моделей. Для загрузки настоящих моделей на пустом тестовом видеопотоке: `/tests/browser.html?models=real`. Это проверяет загрузку WASM и inference, но не качество распознавания лица. Стенд не включается в `dist` и недоступен в production-сборке.

## Ручная приёмка на iPad

1. В Safari по HTTPS разрешить камеру. Проверить отказ и повторный запуск.
2. Пройти центр → левая ладонь → правая ладонь, проверить анатомические стороны при зеркальном видео.
3. Выполнить тренировочный свайп вправо; в тесте проверить четыре направления, диагональ, короткое касание, два пальца и «Не различаю».
4. Убрать руку или отвернуться: спустя примерно 0,5 с символ скрыт. Вернуть руку: другой символ того же размера, счёт не изменился.
5. Проверить нормальный взгляд на центр, кнопку «Не различаю» и разные части поля свайпа, в очках и без, при обычном комнатном освещении, на 40 и 70 см.
6. Повернуть iPad в середине теста: повторная настройка, ранее принятые ответы сохранены. Проверить обе ориентации и прокрутку.
7. Переключить вкладку, заблокировать экран, вернуться: старый кадр не разрешает ответы. При остановке потока повторить запуск.
8. Завершить десять ответов: два результата из пяти, индикатор камеры устройства гаснет. Проверить повтор.

## Как устроено

- `src/video-analysis/vision.ts`: эвристики и калибровка; допуски собраны в `LIMITS`.
- `src/video-analysis/analyzer.ts`, `index.ts`: загрузка моделей и публичный API независимой библиотеки.
- `src/session.ts`: последовательность, фильтрация свайпов и защита от повторных ответов.
- `src/camera.ts`: фронтальная камера демо, ограничение частоты и жизненный цикл; анализ выполняется через общую библиотеку.
- `src/main.ts`, `src/style.css`: интерфейс и события.
- `openspec/changes/camera-vision-demo`: подтверждённые требования, решение и задачи.

Взгляд оценивается по радужкам и геометрии головы относительно калибровки, прикрытие — по пересечению области глаза с многоугольником руки. Выпуклая оболочка руки может перекрывать промежутки между пальцами: это сознательное упрощение демо, не гарантия окклюзии. Face Landmarker иногда теряет лицо за ладонью: приложение показывает неизвестное состояние, а не разрешает тест. Прикрытый глаз исключается из оценки взгляда. Расстояние 40–70 см задаётся инструкцией, автоматически не измеряется.

Размеры E — 120, 96, 72, 54, 40 CSS-пикселей; это не медицинская шкала, физический размер экрана не калибруется. Данные хранятся только в оперативной памяти страницы. Ни видео, ни ответы не отправляются, нет аналитики и истории. Браузер загружает модели и WASM с того же сайта.

## Модели и зависимости

MediaPipe Tasks Vision: [официальная документация лица](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/web_js) и [руки](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js).

В `public/models` находятся официальные модели Google, версия пути `float16/1`:
- https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/1/face_landmarker.task
- https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/1/hand_landmarker.task

WASM автоматически копируется из установленного `@mediapipe/tasks-vision` при запуске/сборке. Для переноса проекта сохраните модели и lockfile. OpenSpec 1.16.0 установлен локально в `.tools/bin/openspec`; бинарник исключён из Git.

Приложение поддерживает книжную и альбомную ориентации. На iPad в книжной ориентации панель камеры находится под основным экраном, в альбомной — сбоку. Поворот при включённой камере запускает повторную калибровку; уже принятые ответы сохраняются.

## Публикация на GitHub Pages

Проект подготовлен для репозитория `SalvorGardin/eye_test`. После публикации стандартный адрес: https://salvorgardin.github.io/eye_test/.

1. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
2. Отправьте изменения проекта, включая `.github/workflows/pages.yml`, `pnpm-lock.yaml` и оба файла `public/models/*.task`, в ветку `main`.
3. Во вкладке **Actions** дождитесь успешного `Publish demo to GitHub Pages`. Если изменения уже отправлены, запустите его через **Run workflow** для `main`.
4. Откройте адрес из результата Deploy или Settings → Pages. На iPad открывайте страницу в Safari и разрешите доступ к камере.

Workflow использует Node 24 и pnpm 11.25.0, устанавливает зависимости по lockfile, запускает тесты и публикует только `dist`. Модели входят в репозиторий, WASM копируется при сборке. Секреты и отдельная ветка `gh-pages` не нужны. `dist`, исходные тестовые стенды и архив библиотеки вручную загружать не нужно.

Путь берётся из `actions/configure-pages`: для этого репозитория `/eye_test/`, для корневого сайта или настроенного собственного домена — `/`. Тот же путь автоматически получает анализатор через `import.meta.env.BASE_URL`. Локальная разработка по-прежнему работает в корне. Камера требует HTTPS; стандартный адрес Pages его предоставляет.

Локальная проверка сборки с путём репозитория:

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm run build --base /eye_test/
pnpm exec vite preview --base /eye_test/ --host 127.0.0.1
```

Откройте `http://127.0.0.1:4173/eye_test/`. После первой публикации проверьте оба режима и запуск камеры на реальном iPad: локальная сборка не заменяет проверку браузера устройства.

Схема публикации соответствует [официальной инструкции Vite для GitHub Pages](https://vite.dev/guide/static-deploy#github-pages).

## Размещение на собственном сервере

Для `https://darkciz.ru/eye-test/`: `pnpm run build:server` создаёт `dist-server/`. Подробности установки, текущий статус сервера и команда завершения: [docs/darkciz-deployment.md](docs/darkciz-deployment.md).

В панели камеры обоих режимов доступно цифровое увеличение 1–3×. Оно применяется к превью и кадру анализа. После смены масштаба калибровка повторяется, принятые ответы сохраняются. Настройка действует до перезагрузки страницы. В библиотеке 0.2.0 доступны `VideoAnalyzer.create({ assetsBaseUrl, zoom })`, `analyzer.setZoom(zoom)` и `analyzer.zoom`; внешний проект сбрасывает свою калибровку самостоятельно.
