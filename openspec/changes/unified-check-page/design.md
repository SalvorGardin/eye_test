# Design
## Context
Основной интерфейс использует один Camera, Calibration и TestSession. Отдельный пример подключения библиотеки работает на своём сервере и предназначен для проверки пакета.
## Goals / Non-Goals
**Goals:** два режима в одном основном приложении без дублирования моделей и камеры.
**Non-Goals:** изменение публичного API, новый фреймворк, роутер и серверные запросы API.
## Decisions
- Добавить home и api в существующий экранный автомат, mode = vision/api/null. Общие камера и индикаторы переиспользуются; на главной боковая панель скрыта.
- Режим API отображает JSON Observation и калибровку. Её этапы идут в этом экране, а не ведут к тренировке. Анализ выполняется тем же VideoAnalyzer через Camera.
- Все переходы к выбору и в новый режим проходят через один сброс: actionGeneration, Camera.stop, Calibration.reset, новый TestSession, очистка жестов и ошибок.
- Устаревшие значения заменяются unknown перед выводом; JSON задаётся через textContent. При повороте API калибруется заново и остаётся в своём режиме.
- Две карточки — обычные кнопки, адаптивная сетка, без дополнительных зависимостей. Проверка браузерным стендом с контролируемым потоком, существующие unit-тесты и production-сборка.
## Risks / Trade-offs
- Позднее завершение запуска → существующий счётчик поколений отменяет переход, Camera закрывает ресурсы отменённого запуска.
- Смешивание калибровки и режима → проверять API → главная → зрение и обратный переход в браузере.

## Orientation
В книжной ориентации до 1024 px камера располагается компактной панелью под основным экраном. В альбомной сохраняются две колонки; при небольшой высоте уменьшаются отступы. Поворот сбрасывает текущие кадры и жест, запускает существующую калибровку без удаления принятых ответов. Оба режима поясняют причину повторной настройки.
